## 严重缺陷

### [严重-001] Note.java `@TableLogic` 与手动软删除逻辑冲突 — 回收站功能完全不可用

- **文件**: `Note.java` 第38~39行，`NoteServiceImpl.java` 多处
- **问题描述**:  
  `Note.java` 在 `isDeleted` 字段上标注了 `@TableLogic(value = "0", delval = "1")`。MyBatis-Plus 的 `@TableLogic` 会自动在**所有 SELECT 查询**中追加 `WHERE is_deleted = 0`，包括 `selectById()`、`selectList()`、`selectCount()` 等。但是代码中 `NoteServiceImpl` 的 `recycle()`、`recover()`、`permanentDelete()` 均通过**手动设置 `isDeleted` 值 + `updateById()`** 来管理软删除状态，而非使用 MyBatis-Plus 的 `deleteById()` 逻辑删除机制。

  这导致以下所有回收站相关操作**必然失败**：

  1. **回收站列表查询**（`list()`）: 传入 `isDeleted=1` 时手动追加 `eq(Note::getIsDeleted, 1)`，但 `@TableLogic` 自动追加 `is_deleted = 0`，最终 WHERE 条件为 `is_deleted = 0 AND is_deleted = 1`，查不到任何已删除笔记。
  2. **查看已删除笔记详情**（`detail()`）: `selectById()` 自动追加 `is_deleted = 0`，已删除笔记永远查不到。
  3. **恢复笔记**（`recover()`）: `selectById()` 无法找到已删除笔记，恢复操作直接抛 404。
  4. **永久删除**（`permanentDelete()`）: `selectById()` 无法找到已删除笔记，永久删除操作直接抛 404。
  5. **笔记本删除校验**（`NotebookServiceImpl.delete()`）: 调用 `noteMapper.selectCount()` 统计笔记时，`@TableLogic` 只统计非删除笔记（漏掉了回收站中的笔记），与 PRD "含回收站" 的设计意图不符。

- **影响**: 回收站模块（软删除、恢复、永久删除、回收站列表）全线瘫痪，属于 V0.1 核心功能阻断。同时笔记本删除校验不完整。
- **修复建议**:  
  **方案A（推荐）**: 移除 `Note.java` 上的 `@TableLogic` 注解，保留现有手动软删除逻辑（与 PRD 流程一致）。  
  **方案B**: 删除所有手动 `isDeleted` 操作代码，改用 MyBatis-Plus 的 `deleteById()` 做逻辑删除。但需要验证 `updateById` 更新 `isDeleted=1` 是否会被 `@TableLogic` 拦截，整体改动面较大。

### [严重-002] NoteEditor.vue 保存时未传递 `notebookId` — 编辑保存必然失败

- **文件**: `components/NoteEditor.vue` 第145~149行，`views/NoteEdit.vue` 第96~101行
- **问题描述**:  
  `NoteEditor.vue` 的 `save()` 函数发送的请求体只有 `{id, title, content}`，不包含 `notebookId`。后端 `NoteSaveDTO` 中 `notebookId` 字段标注了 `@NotNull(message = "笔记本不能为空")`，Controller 层有 `@Valid` 校验。因此每次编辑保存都会触发 `MethodArgumentNotValidException`，返回 400 错误，笔记实际**不会落库保存**。

  同样的问题也出现在 `views/NoteEdit.vue` 的 `onTagsUpdate()` 函数（第96~101行），更新标签时也缺少 `notebookId`。

  此外，Home.vue 的 `onTagsUpdate()`（第183~188行）也存在相同问题。

- **影响**: 笔记编辑保存功能完全失效。用户无法修改现有笔记的标题、内容或标签。
- **修复建议**:  
  1. `NoteEditor.vue` 在 `loadNote()` 时存储 `notebookId`（响应数据中已包含），并在 `save()` 时一并发送。
  2. `NoteEdit.vue` 和 `Home.vue` 的 `onTagsUpdate()` 同样需要携带 `notebookId`。
  3. 或者后端 `NoteSaveDTO` 在修改场景下对 `notebookId` 不做 `@NotNull` 校验，而是在 Service 层从已有数据中取。

### [严重-003] TagSelect.vue 创建新标签后响应处理为空导致 TypeError

- **文件**: `components/TagSelect.vue` 第134~136行
- **问题描述**:  
  创建新标签时调用 `saveTag()` API，后端 `TagController.save()` 返回 `Result.success()`（data 为 null）。前端请求拦截器 `request.js` 提取 `res.data`，因此 `saveTag()` 的返回值 `saved` 为 `null`/`undefined`。代码 `saved.id || saved` 会触发 `TypeError: Cannot read properties of null`，导致 `catch` 块捕获异常，新标签无法添加到 UI 的标签列表中。

- **影响**: 用户在编辑器中创建新标签后，标签不会出现在已选列表中，且无错误提示。
- **修复建议**:  
  **后端**: 修改 `TagController.save()` 返回新建的 Tag 对象（含 id）。  
  **前端**: `TagSelect.vue` 中创建标签后应重新调用 `getTagList()` 拉取全量标签列表，并从中匹配新建标签。

### [严重-004] RecycleBin.vue 删除时间字段显示错误

- **文件**: `views/RecycleBin.vue` 第53行，`NoteListVO.java` 缺少字段
- **问题描述**:  
  回收站列表展示的删除时间使用了 `note.updatedAt`（最后更新时间），而非 `note.deletedAt`（软删除时间戳）。PRD 回收站表格设计明确要求展示"删除时间"。`NoteListVO` 中也没有映射 `deletedAt` 字段。

- **影响**: 回收站显示的时间不是真正的删除时间，用户无法判断笔记何时被删除。不符合 PRD 设计。
- **修复建议**:  
  1. `NoteListVO` 添加 `private LocalDateTime deletedAt;` 字段。  
  2. `NoteServiceImpl.list()` 中映射 `vo.setDeletedAt(note.getDeletedAt())`。  
  3. `RecycleBin.vue` 中 `formatTime` 使用 `note.deletedAt`。

## 一般缺陷

### [一般-001] NoteList 列表查询存在 N+1 查询性能问题

- **文件**: `NoteServiceImpl.java` 第141~167行
- **问题描述**:  
  `list()` 方法在 `stream().map()` 内，对每条笔记**逐条**执行 `notebookMapper.selectById()` 获取笔记本名称，以及 `noteTagRelMapper.selectList()` + `tagMapper.selectById()` 获取标签。对于一个分页 20 条的查询，可能产生 20 + 20×N（标签数）次额外数据库查询。

- **影响**: 当笔记数量较多时，列表页面加载明显变慢。
- **修复建议**: 批量查询。先收集所有 `notebookId` 和所有 `noteId`，分别用 `selectBatchIds` 一次查询所有笔记本和所有关联标签，然后在内存中组装。

---

### [一般-002] NotebookServiceImpl.save() 修改时未校验笔记本是否存在

- **文件**: `NotebookServiceImpl.java` 第40~44行
- **问题描述**:  
  修改笔记本时未检查 `dto.getId()` 对应的记录是否存在。如果传入不存在的 id，`updateById()` 会静默执行（影响行数为 0），前端收到成功响应但实际未修改任何数据。

- **影响**: 低 — 通常不会传入不存在的 id，但缺乏防御性校验。
- **修复建议**: 修改前先 `selectById` 检查记录是否存在，不存在则抛 `BusinessException(404)`。

---

### [一般-003] NotebookServiceImpl.save() 未校验 parentId 指向的笔记本是否存在

- **文件**: `NotebookServiceImpl.java` 第34~50行
- **问题描述**:  
  创建或修改笔记本时，未校验 `parentId`（非 0 时）是否指向数据库中实际存在的笔记本。可能创建出孤儿子笔记本。

- **影响**: 笔记本树中可能出现父节点不存在的孤儿节点，导致树结构异常。
- **修复建议**: 当 `parentId != null && parentId != 0` 时，先查询 `notebookMapper.selectById(parentId)` 确认父笔记本存在。

---

### [一般-004] NotebookServiceImpl.save() 未校验循环嵌套

- **文件**: `NotebookServiceImpl.java`
- **问题描述**:  
  PRD 第6.1节明确要求 `parent_id` "不能为自己的子孙节点（防止循环嵌套）"。当前代码完全没有这个校验。将一个父笔记本的 `parentId` 改为其子笔记本的 id，会形成循环嵌套，导致 `tree()` 方法中的 `buildTree()` 递归无限循环、StackOverflowError。

- **影响**: 可能导致笔记本树接口崩溃，后端不可用。
- **修复建议**: 修改笔记本时，若 `parentId` 改变，递归检查新父节点是否为当前节点的子孙节点。

---

### [一般-005] NoteServiceImpl.save() 未校验 notebookId 是否存在

- **文件**: `NoteServiceImpl.java` 第47~65行
- **问题描述**:  
  创建笔记时仅通过 DTO 的 `@NotNull` 确保 `notebookId` 非空，但未校验该 ID 是否真实存在于 `notebook` 表。可创建出挂在不存在笔记本下的笔记。

- **影响**: 笔记列表中 `notebookName` 显示为空白字符串，用户体验差。
- **修复建议**: `save()` 方法开头增加 `notebookMapper.selectById(dto.getNotebookId())` 校验。

### [一般-006] NoteServiceImpl.save() 未校验 tagIds 是否存在

- **文件**: `NoteServiceImpl.java` 第87~97行
- **问题描述**:  
  保存笔记关联标签时，未校验 `tagIds` 中的每个 id 是否真实存在于 `tag` 表。可写入无效关联数据。

- **影响**: 详情接口中关联到不存在的标签时展示为空，产生脏数据。
- **修复建议**: 保存标签关联前，先批量查询 tagIds 存在的记录数，与传入数量比对。

### [一般-007] NoteSaveDTO 缺少长度校验

- **文件**: `NoteSaveDTO.java` 第23~24行
- **问题描述**:  
  `title` 字段只有 `@NotBlank`，缺少 `@Size(max = 256)`。PRD 第6.2节规定标题 1~256 字符。同时 `name` 字段也没有校验不允许纯空格。

- **影响**: 可存入超长标题，与数据库 VARCHAR(256) 可能冲突（取决于 MySQL 严格模式，可能截断或报错）。
- **修复建议**: 添加 `@Size(min = 1, max = 256)` 注解。

- **文件**: `NotebookSaveDTO.java` 第21~22行
- **问题描述**:  
  `name` 字段只有 `@NotBlank`，缺少 `@Size(min = 1, max = 128)`。PRD 第6.1节规定笔记本名称 1~128 字符。

- **影响**: 可能存入超长笔记本名称，与数据库 VARCHAR(128) 冲突。
- **修复建议**: 添加 `@Size(min = 1, max = 128)` 注解。

### [一般-009] TagSaveDTO 缺少长度和颜色格式校验

- **文件**: `TagSaveDTO.java` 第20~24行
- **问题描述**:  
  `name` 只有 `@NotBlank`，缺少 `@Size(max = 64)`；`color` 没有正则校验 hex 格式（PRD 第6.3节）。

- **影响**: 可能存入超长标签名或非法颜色值。

### [一般-010] request.js 错误处理的 toast 回调在组件挂载前可能未设置

- **文件**: `api/request.js` 第19~21行、第29~31行；`views/Home.vue` 第114~119行
- **问题描述**:  
  拦截器通过 `window.__toastFn` 显示错误提示，但 `__toastFn` 在 `Home.vue` 的 `onMounted()` 中才设置。如果在组件挂载前触发了 API 错误（如应用初始化时的请求），错误会被静默吞噬。

  另外，`NoteEdit.vue` 也在 `onMounted` 中设置 `__toastFn`，两个视图会互相覆盖。

- **影响**: 早期 API 错误无提示，用户可能不知道发生了什么。
- **修复建议**: 使用 provide/inject 或 Pinia store 全局管理 toast，而非全局变量。或者将 toast 函数在 `main.js` 中初始化。

### [一般-011] NotebookTree 右键菜单删除操作未区分"非空"的具体原因

- **文件**: `components/NotebookTree.vue` 第131~142行
- **问题描述**:  
  删除笔记本失败时，错误提示只显示拦截器返回的通用消息（"笔记本非空，无法删除"），用户不知道是因为有子笔记本还是有笔记。PRD 第5.3.2节和 PRD 第9节提到应分别提示。

- **影响**: 用户体验一般，用户不清楚如何做才能删除该笔记本。
- **修复建议**: 后端 `NotebookServiceImpl.delete()` 区分两种非空情况的错误消息（子笔记本 vs 笔记）。

### [一般-012] InnerLinkServiceImpl.parseAndSave 缺少事务隔离，存在并发竞争

- **文件**: `InnerLinkServiceImpl.java` 第33~77行
- **问题描述**:  
  `parseAndSave` 使用"先删除旧链接，再逐个插入"的模式。如果同一笔记被并发保存（虽然概率低），可能出现 A 删除后 B 也删除，然后 A 和 B 都插入，导致链接记录错误。另外 `selectCount` + `insert` 的 INSERT IGNORE 模拟不是原子操作。

- **影响**: 极低概率的并发问题。在单用户本地部署场景下几乎不会触发，但在 V0.2 API 对外暴露时需注意。
- **修复建议**: 使用数据库层面的 `INSERT ... ON DUPLICATE KEY UPDATE` 或 MyBatis-Plus 的 `saveOrUpdate` + 唯一索引。

### [一般-013] RecycleBin.vue 批量操作使用循环逐条调用而非后端批量接口

- **文件**: `views/RecycleBin.vue` 第149~170行
- **问题描述**:  
  `onBatchRecover` 和 `onBatchPermanentDelete` 使用 for 循环逐条调用 API。后端虽然没有 `batch-recover` 和 `batch-permanent-delete` 接口，但后端有 `batch-recycle` 接口。对于恢复和永久删除，应提供对应的批量接口。

- **影响**: 批量操作效率低，前端逐个请求；如果中途失败，已成功的操作不会回滚。
- **修复建议**: 后端新增 `POST /api/note/batch-recover` 和 `DELETE /api/note/batch-permanent` 批量接口。

### [一般-016] NoteList.vue 的 favorite toggle 前端乐观更新与后端状态不一致

## 建议项

### [建议-001] NoteEditor 切换笔记时自动保存缺少 notebookId 校验（与严重-002 关联）

- **文件**: `components/NoteEditor.vue`，`views/Home.vue` 第150~152行
- **问题描述**:  
  Home.vue 中 `onSelectNote` 在切换笔记前调用 `noteEditorRef.value.save()` 保存当前笔记。但由于严重-002，保存实际上会失败，导致当前笔记的修改丢失。

- **影响**: 切换笔记时用户的未保存修改丢失。
- **修复建议**: 与严重-002 一并修复。

---

### [建议-002] NoteServiceImpl.save() 修改笔记时未保留 `createdAt` 字段

- **文件**: `NoteServiceImpl.java` 第64~77行
- **问题描述**:  
  修改笔记时 `note.setUpdatedAt(LocalDateTime.now())` 但没有保留 `note.setCreatedAt(existing.getCreatedAt())`。虽然 MyBatis-Plus 的 `updateById` 更新全字段，但新构造的 `note` 对象中 `createdAt` 为 null，会覆盖掉数据库中的原值。

- **影响**: 修改笔记后 `created_at` 被置为 NULL，创建时间丢失。
- **修复建议**: 修改时设置 `note.setCreatedAt(existing.getCreatedAt())`。

### [建议-003] 后端笔记列表接口缺少 PRD 规定的 page 最小值校验

- **文件**: `NoteServiceImpl.java` 第135~136行
- **问题描述**:  
  PRD 第6.5节规定 page ≥ 1，size 范围 [1, 100]。代码中有 size 上限校验（≤100），但没有 page 的最小值校验（`page > 0` 已覆盖）。不过没有对 page 过大时的友好处理——传入 page=99999 会查询出一个空页，未做截断处理。

- **影响**: 无功能影响，但接口健壮性可提高。
- **修复建议**: 可增加 page 最大值校验，或在 page 超出总页数时自动修正。

### [建议-004] 缺少操作日志记录

- **文件**: 全局
- **问题描述**:  
  除了 `GlobalExceptionHandler` 中的 warn/error 外，核心业务操作（创建笔记、删除笔记、永久删除、恢复笔记）没有任何 INFO 级别的操作日志。不利于问题排查和审计。

- **影响**: 出现问题时难以追踪操作历史。
- **修复建议**: 在关键业务方法（save/delete/recycle/recover/permanentDelete）中添加 `log.info` 记录操作类型、目标 ID 和操作结果。

### [建议-005] NoteServiceImpl.permanentDelete 物理删除后潜在数据残留

- **文件**: `NoteServiceImpl.java` 第256~269行

### [建议-006] MarkdownParseUtil 正则对含 `[` 字符的标题处理不精确

- **文件**: `MarkdownParseUtil.java` 第15行
- **问题描述**:  
  正则 `\[\[(.+?)\]\]` 对于 `[[[note]]]` 这样的边界情况，会提取出 `[note` 而非 `[note]`（因为 `.+?` 非贪婪匹配时，中间的 `]` 会先匹配到外层的 `]]`）。虽然在正常使用中极少出现这种情况，但对于包含 `[` 或 `]` 字符的标题可能解析错误。

- **影响**: 极低 — 笔记标题中通常不含方括号。
- **修复建议**: 可以将正则改为 `\[\[([^\[\]]*(?:\[[^\]]*\][^\[\]]*)*)\]\]` 以处理嵌套方括号，或至少在文档中说明限制。

### [建议-007] AsyncTaskConfig 线程池未配置 awaitTermination 时长

- **文件**: `AsyncTaskConfig.java` 第22~37行
- **问题描述**:  
  虽然设置了 `setWaitForTasksToCompleteOnShutdown(true)`，但未配置 `setAwaitTerminationSeconds`，默认会无限等待。如果异步任务卡死，会导致应用无法正常关闭。

- **影响**: 潜在的重启阻塞风险（V0.1 异步任务未启用，当前无影响）。
- **修复建议**: 增加 `executor.setAwaitTerminationSeconds(30)`。

### [建议-008] RecycleBin.vue 分页按钮边界情况

- **文件**: `views/RecycleBin.vue` 第67行
- **问题描述**:  
  下一页按钮的禁用条件 `page >= Math.ceil(total / size)` 在 `total=0` 时 `Math.ceil(0/20)=0`，`page(1) >= 0` 为 true，下一页被禁用（正确）。但如果有数据删除导致 total 刚好被 size 整除时，`Math.ceil(20/20)=1`，`page(1) >= 1` 为 true，下一页被禁用（正确）。逻辑上没问题，但 `Math.ceil` 针对整数除法可能产生浮点误差，建议用 `Math.ceil(total.value / size.value)` 或直接用 `totalPages.value`（NoteList.vue 已采用此方式）。

- **影响**: 极低。
- **修复建议**: 统一使用 `totalPages` 计算属性，保持与 NoteList.vue 一致。

| 场景 | 风险 | 说明 |
|------|------|------|
| 笔记本名称允许纯空格 | 中 | PRD 规定不允许纯空格，`@NotBlank` 仅拦截空字符串，`"  "` 可能通过 |
| 创建笔记时 notebookId=0 | 中 | `@NotNull` 仅拦截 null，`0L` 会通过校验但后台无 id=0 的笔记本 |
| 并发保存同一笔记 | 低 | PRD 第9节明确 V0.1 不做乐观锁，后保存覆盖先保存，预期行为 |
| 同名词笔记本 | 低 | PRD 允许同名，但不建议 |
| `[[` 嵌套引用（如 `[[[[a]]]]`） | 低 | MarkdownParseUtil 正则可能错误提取 |
| 超长 Markdown 内容 | 中 | content 使用 LONGTEXT 无长度限制，前端 textarea 可能性能下降 |
| 回收站笔记被恢复后 notebookId 对应的笔记本已被删除 | 中 | 当前代码未处理此场景，恢复后笔记挂在已删除笔记本下成为孤儿 |
| 笔记本排序负值 | 低 | sort_order 允许负数，MySQL INT 可存储，但 UI 排序可能不符合预期 |
| 特殊字符标签名（emoji） | 低 | 标签名仅限 VARCHAR(64)，emoji 可能占用 4 字节需 utf8mb4 支持 |
| 标签颜色值非 hex 格式 | 中 | `TagSaveDTO.color` 未做格式校验，可存入任意字符串 |
| 标签名大小写去重 | 低 | `WHERE name = 'xxx'` 取决于 MySQL 字符集排序规则（默认不区分大小写） |
| 空笔记本删除后父节点仍为空且可删除的级联逻辑 | 低 | 无级联删除，需手动逐层删除 |
| 前端网络断开时自动保存失败无用户感知 | 中 | autoSave 的 catch 块静默处理，用户不知道自动保存失败 |
| 笔记编辑器关闭浏览器时未保存提示 | 高 | 当前无 `beforeunload` 监听，未提示用户保存 |
